# 下一位开发者的交接入口

更新：2026-09-19。先读 [README](../README.md) 启动工程，再读 [剩余目标](remaining-goals.md)。历史准备报告可能写“未实现”，不要把历史状态当成当前现状。

## 用户当前方向

本地部署、浏览器访问的面试辅助系统。希望面试官按人清楚切换，问题保持自然交流，兼顾项目能力与常规话题，不做持续“查真假”的盘问。用户关心实际面试体验与甲方交付，不追求复杂框架。

P0/P1 的技术链路已实现。后续追加了竞赛基础分析、网页虚构人物演示、深色模式、批量简历导入、独立候选人页面和常规开场。语音、云端、多 Agent、自动评分等仍暂缓。

用户计划之后要求上传 GitHub，当前尚未授权具体仓库上传。本机保存了 DeepSeek 配置，接手者应在自己的设置页填写自己的密钥，不能复制本机数据库作为发布默认数据。

## 代码入口

- `backend/main.py`：项目、候选人、单文件上传、批量导入单项接口、设置。
- `backend/interview_api.py`：提纲、会话、开场、回答、追问、人工复核、报告。
- `backend/interview_service.py`：输入快照、模型提示词、引用校验、累计声明状态。
- `backend/interview_models.py`：Pydantic 输出与请求合同；新增字段使用默认值兼容旧记录。
- `backend/providers/`：OpenAI-compatible 非流式调用，DeepSeek 已真实调用验收。
- `backend/database.py`、`migrations.py`：SQLite 与旧库迁移。JSON 列保存提纲和回合。
- `frontend/src/main.tsx`：首页、项目、独立候选人、设置、主题开关及路由。
- `frontend/src/BatchImport.tsx`：姓名确认、逐项导入、成功/失败状态。
- `frontend/src/workflow.tsx`：生成、常规开场选择、面试与报告。
- `frontend/src/theme.css`：两套颜色变量及候选人布局；基础样式在 style.css。
- `scripts/backup.py`：离线备份恢复，密钥排除，新目录恢复。

## Skill 如何工作

这是业务工程内的提示词资源，不是安装到 Codex 的全局插件，也不是可执行 Agent。`backend/skills.py` 只读 `skills/<id>/SKILL.md`，校验路径和体积，返回内容及哈希。

| Skill | 默认选中 | 作用 |
| --- | --- | --- |
| project-requirement | 是 | 从项目/JD提取必要能力及原文依据 |
| question-design | 是 | 项目题/情境题、自然语气、避免重复盘问 |
| roles-backend | 否 | 后端岗位的接口、数据、异常、测试讨论范围 |
| competition-analysis | 否 | 竞赛经历的岗位关联、个人贡献、有限参考价值与未知项 |
| example | 否，生成选项隐藏 | 目录规范示例 |

选择后必须预览，再确认发送。Skill 内容、版本、简历、需求、模型配置和交流方式进入输入快照与哈希；生成拒绝过期预览。后续专业回答分析继续发送同一 Skill 快照，修改磁盘文件不会悄悄改变已有会话的资源版本。

注意：Skill 被发送不等于模型必然遵守。JSON和连续原文引用有硬校验；语气、关联性、推理质量仍主要依赖模型和人工复核。系统提示词自身目前没有完整的版本执行引擎，升级后老会话会使用新代码，Skill 快照则保持不变。

常规开场没有模型调用，不发送开场历史供后续能力分析；保留本地记录并导出。竞赛评价来源策略待用户确定，不要求只用官方数据。不要擅自做绝对含金量排名。

## 关键行为与取舍

- 单机、无登录，API 仅绑定 loopback；不是可直接放公网的多人产品。
- React 开发入口 8765，FastAPI 8766，Vite 代理 `/api`。还没有正式运行包。
- 每次批量导入最多 20 文件，逐项 POST；每项先解析再在事务中创建候选人和简历。其他文件失败不回滚成功项。请求结果丢失尚无幂等 token，重试前查列表。
- 一份文件默认对应一人，不猜姓名，不自动把同名文件合并；姓名从文件名预填，用户确认。同一人的简历版本在独立档案上传。
- 主题仅存浏览器 localStorage，首次随系统；不存个人简历数据到 localStorage。
- UI 新会话默认有开场，API 默认 none 保持原调用兼容。总轮数包含开场；开场不计专业能力覆盖。达到上限或无后续问题会结束，也可人工提前结束。
- 回答失败不覆盖已有记录。未提交草稿仅页面内存，刷新/换人前需处理。
- 采用 `UNKNOWN` 不覆盖旧支持线索的累计状态规则。原始模型回合输出不改写；明确矛盾仍可改变状态。累计标签并非独立真实性证明。
- 专业题的自动下一题优先补未覆盖能力，也允许面试官采用建议追问。尚无完整改题、跳题和时间预算。
- 脱敏不是万能识别，发送前看预览。Windows Key 使用当前用户 DPAPI，备份排除 Key。

## 验证与演示

在工程目录运行 `.\.venv\Scripts\python.exe -m pytest backend/tests -q`；前端目录运行 `npm.cmd run build`。当前 26 项后端测试通过，依赖内部有两条弃用警告。浏览器验收记录见 [本轮记录](verification-experience.md)。

真实浏览器测试发现过追问的 resume_quote 错用回答文本的问题：专业回答上下文现在包含预览中已确认的简历原文；提示明确区分 answer_quote 与 resume_quote，并允许无简历引文时留空。结构/引用失败最多修正一次，再失败则不保存本轮。对应测试验证最多两次模型调用，不降低原文引用要求。

本机演示数据不会随 GitHub 克隆出现：项目 #4 是陈亦舟完整 5 轮虚构面试，会话 #3；项目 #5 是多候选人演示。可提交的纯虚构示例文本与报告在 `docs/examples/`，不包含真实个人资料。

## 建议接手顺序

1. 启动并走一遍上传→预览→生成→开场→回答→报告。
2. 阅读 remaining-goals，先与岗位负责人校准问题长度、追问停止和真实记录方式。
3. 补人工控场和收尾流程，再做 Windows 可分发运行包及干净机器验收。
4. 用户明确要求后再配置 GitHub 远端和上传；发布前复查忽略项和 PyMuPDF 的分发许可路线。不要在未核对许可前复制外部参考仓库源码。
