## 实际操作与分工

用 Playwright 操作真实网页 8765，没有将 API 重定向到测试服务，也没有直接向数据库插入结果。通过表单创建项目和候选人、上传 TXT、检查解析文本、勾选四个 Skill、预览输入、确认发送、生成提纲、开始面试、逐轮填写回答、选择一次动态追问、查看和下载报告。

DeepSeek / deepseek-flash 真实生成提纲和分析；Codex 按虚构人设编写并在网页填入回答。不是两位真人面试，不是招聘效果验证，也不是预先写好的模型结果。

初始题量 4，道数上限 5（含追问）。五轮顺序：

1. PDF 解析与空文本处理。
2. 采用模型根据第一轮回答提出的追问：阅读顺序问题如何发现和处理。
3. 大模型调用超时与错误处理。
4. SQLite 借还接口的数据结构和并发情境。
5. Windows 本地交付、配置和备份的情境题。

候选人主动说明复杂版面、服务端幂等、并发测试、Windows 打包的不足，未塑造成全能人物。达到 5 轮后自动结束，未额外展开竞赛盘问。

## 竞赛 Skill 到了哪一步

四个选定资源：project-requirement、question-design、roles-backend、competition-analysis。内容和版本哈希保存于提纲输入；回答分析沿用相同 Skill 快照，不重新加载修改后的文件。页面可查看本次选定资源。

新增 Competition 数据结构，分析字段有赛事名称、原文引用及位置、届次/赛道、奖项层级、赛制、竞争强度、岗位相关性、个人贡献、参考价值、待确认项和一个可选讨论问题。生成记录、会话页和 Markdown 报告均有输出。旧提纲缺少该字段仍可打开。

这次模型识别“青禾校园软件创新赛，校级团队二等奖”，说明与接口、数据库实践相关，但不足以证明生产交付能力；获奖率、参赛规模、竞争强度未知。赛事本身是虚构的，没有进行官方核验。

已做：基于简历的有限分析、可追溯引用、明确未知、岗位关联、可见结果和全流程 Skill 传入。

未做：官方赛事知识库、联网检索、证书查验、真实赛事认可度校准。不能将本版本称为已完成的“权威竞赛含金量数据库”，也不能把模型意见冒充官方结论。

## 测试与修复

22 项后端测试通过，TypeScript/Vite 构建通过。新增覆盖：竞赛分析必须显式选中 Skill、伪造原文引用被拒绝、竞赛结果持久化并进入报告、回答分析收到原 Skill 快照。

网页模拟发现：后续回答未讨论某声明时，模型可能输出 UNKNOWN，原实现会覆盖此前支持线索。已修复累计状态：UNKNOWN 不清除既有线索，实际矛盾仍可改变状态；从保存的回合记录重新计算显示，原始模型输出不改写。增加多轮回归测试。真实模拟不为修饰结果重新调用模型。

后端重启并刷新后，五轮回答与竞赛结果保留。页面下载报告成功。截图位于 output/playwright/web-demo-competition.png，属于忽略的测试产物。浏览器控制台只有 React 开发提示，无运行错误。

## 本次观察到的产品不足

- 部分问题仍将几个子问题放在同一句，Skill 约束是提示，尚没有有效的质量验收规则。
- 候选人解释版面处理不足后，模型又建议继续深挖近似主题；此次没有再次采用，实际转入其他能力。追问停止条件仍需校准。
- 一项技能列表被模型笼统关联到多个回答；引用真实存在不等于推理正确。需要面试官复核。
- 这不是完整的 25 分钟真人面试，没有开场计时、候选人反问环节，也不能用 5 轮自动结束证明所有能力均已评估。
- 竞赛分析保持辅助定位，不额外占用题量；有官方材料后才有条件进一步分析竞争强度。
